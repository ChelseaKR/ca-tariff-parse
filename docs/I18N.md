# Internationalization

i18n status: N/A

Reason: this project parses tariff documents that their publishers issue in
English, and it ships no user-facing message catalog. Its outputs are a JSON
document whose keys are stable identifiers and whose values are verbatim
quotations from the source, plus a small amount of operator-facing terminal
text. Translating the quoted values would break the guarantee that every
emitted value matches the cited document word for word, which is the point of
the project.

## What would change this

Adding either of the following would make the standard apply, and the
declaration above would be revisited at that point:

- a source document published in a language other than English, or a publisher
  issuing parallel language versions of the same schedule;
- an end-user surface such as a web view or a report generator, as distinct
  from the current operator CLI.

The verbatim `snippet`, `definition` and `text` fields would remain untranslated
in either case. They are evidence, not copy.
